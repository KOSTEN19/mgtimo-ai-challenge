# мгтимо — кабинет студента МГТИМО

Личный кабинет студента для вуза **МГТИМО**. Все ФИО, группы, оценки и номера в прототипе вымышлены.

## Что внутри

- Вход по логину и паролю, профиль студента
- «Сегодня»: ближайшая пара, остаток дня, что требует внимания
- Расписание на день и неделю с числителем и знаменателем, переносы и отмены пар
- Учёба и сессия: как у меня дела, ближайшие даты, прошлые сессии
- Заявки и справки: пять типов услуг, лента статусов
- Уведомления: статусы заявок приходят сами, напоминания о дедлайнах
- Обходной лист с прогрессом
- Новости деканата
- Кабинет сотрудника: очередь заявок и смена статуса (студент получает уведомление)

## Запуск (только Docker, Node на хосте не нужен)

```bash
cp .env.example .env        # на Windows: copy .env.example .env
# в .env замените SESSION_SECRET на длинную случайную строку
docker compose up --build -d
```

Откройте http://localhost:3000. База (SQLite) лежит в томе `mgtimo-data` и переживает перезапуск. Схема и тестовые данные применяются при каждом старте автоматически.

Разработка с горячей перезагрузкой, тоже в Docker:

```bash
docker compose -f docker-compose.dev.yml up --build
```

Остановка: `docker compose down`. Полный сброс данных: `docker compose down -v`.

## Архитектура (прод)

```
:80/:443 → nginx (TLS, rate limit, headers) → web:3000 (внутренняя сеть)
                              ↓
                     access.log → fail2ban на хосте
```

Конфиги: каталог [`deploy/`](deploy/README.md) — nginx, fail2ban, prod Compose.  
Приложение **не** публикует порт наружу; снаружи только edge.

```bash
# сертификаты → deploy/certs/fullchain.pem + privkey.pem
COOKIE_SECURE=true
docker compose -f deploy/docker-compose.yml --env-file .env up -d --build
```

Локально без nginx: `docker compose up --build -d` → http://127.0.0.1:3000

Шрифты и иконки в образе, внешние CDN не нужны.

## Как устроена защита

- Пароли хранятся только как bcrypt-хеш.
- Сессия: подписанный токен в httpOnly-cookie, секрет только в переменной окружения.
- Каждый запрос студента фильтруется по его id из сессии, а не из адреса. Чужую заявку по прямой ссылке открыть нельзя: вместо неё показывается страница «не найдено», данных в ответе нет.
- Сотрудник видит очередь заявок, но не оценки и профили студентов.
- Ошибка входа не раскрывает, что именно неверно, плюс ограничение числа попыток.
- Ключей внешних сервисов в коде и браузере нет.

## Стек

Next.js 15 (App Router), TypeScript, Tailwind CSS 4, Prisma и SQLite, `jose`, `bcryptjs`, `lucide-react` (ISC), шрифт Manrope Variable (SIL OFL).

Для большего числа пользователей достаточно сменить провайдер Prisma на PostgreSQL: доступ к данным идёт только через Prisma.

## Оформление

Современный liquid glass / Solvik-inspired chrome. Тёмная тема по умолчанию, светлая через cookie `mgtimo_theme`. Картинки в `public/art/` (Higgsfield):

| Файл | Назначение |
| --- | --- |
| `bg-dark-*.webp`, `bg-light-*.webp` | архив; app-shell больше не использует — фон в CSS |
| `hero-dark.webp`, `hero-light.webp` | медиа-блок на экране входа |
| `icon-*.png` | 3D-иконки разделов |
| `empty-*.png` | пустые состояния |
| `logo-mark.png` | знак кабинета мгтимо |

Чтобы заменить hero/иконку, положите файл с тем же именем.

## Правило числителя и знаменателя

Нечётная календарная неделя (ISO) — числитель, чётная — знаменатель. Время московское.
